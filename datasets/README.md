# SOAR Ransomware Lab — Public Alert Dataset (EXP-01)

Anonymized, deterministic alert dataset for independent replication of the
SOAR pipeline experiments. No real infrastructure, hostnames, IPs, domains
or malware samples are present — every identifier is synthetic.

## Contents

| File | Purpose |
| --- | --- |
| `soar-ransomware-alerts-v1.jsonl` | 100 labeled alerts (70 malicious, 30 benign), one JSON object per line |
| `MANIFEST.json` | Schema version, seed, counts, and the **SHA-256 reproducibility anchor** of the JSONL |

## Ground truth

Each record carries two non-pipeline fields (consumed by reviewers, not
by the pipeline):

- `expected_verdict`: `malicious` | `benign`
- `expected_pipeline_outcome`: `case_created` | `no_case_or_false_positive`

Malicious alerts must produce a TheHive case (stage `New`/`InProgress`)
with severity ≥ 2; benign alerts must either produce no case or a case
resolved as false-positive stage (`FalsePositive`/`Indeterminate`).

## Anonymization guarantees

| Field | Replacement |
| --- | --- |
| `src_ip`, `c2_ips` | RFC 5737 documentation ranges only (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) |
| `domain`, `url` | `*.soar-dataset.example.com` (RFC 2606 reserved) |
| `hash` | synthetic `sha256(seed, family, index)` — never a real sample |
| `hostname` | `ws-lab-XX` / `srv-lab-XX` |
| `detection_time` | deterministic offset from a fixed epoch, not wall-clock |

## Regenerating (determinism check)

```bash
python scripts/maintenance/build_dataset.py \
    --out datasets/soar-ransomware-alerts-v1.jsonl \
    --malicious 70 --benign 30 --seed 20261108
sha256sum datasets/soar-ransomware-alerts-v1.jsonl
# must equal MANIFEST.json -> jsonl_sha256
```

Same seed ⇒ byte-identical file (verified in
`tests/unit/test_dataset_build.py`).

## Replication methodology (third-party)

1. **Regenerate** the dataset and verify `jsonl_sha256` matches
   `MANIFEST.json` (proves the published bytes are the generated bytes).
2. **Deploy** the stack: `make up` (see `docs/01-getting-started.md`).
3. **Replay** through the measured admission pipeline:
   `docker exec soar_api python /app/scripts/maintenance/replay_dataset.py
   /app/datasets/soar-ransomware-alerts-v1.jsonl --via-api --tag exp-v1`
   (or `--webhook` for the raw Shuffle path, `--dry-run` to validate only).
4. **Score**: for each `alert_id` (`DS-MAL-*` / `DS-BEN-*`) compare
   `expected_pipeline_outcome` with the observed result in TheHive
   (`POST /api/v1/query` on `listCase` filtered by `description` containing
   the alert_id) and KPI aggregates (`GET /api/v1/metrics/kpis`).
5. **Compare** against the reference expectations in `docs/17` §3.31 —
   a replication is consistent when ≥ 95 % of malicious alerts create
   cases and ≥ 90 % of benign alerts produce no case or an FP resolution
   (tolerances account for analyzer coverage variance).
